# What does the game do to a hired pawn on dismiss, lost and re-hire?

Type: research
Status: resolved

## Question

From the type dump (`tools/dump/`), `docs/findings/api-map.md`, and other mods' scripts as API reference
(Arisen's Own, any open-source pawn/Rift mods), find out what the code says about:

1. `PawnManager.dismissPawn` / `onDismissPawn`: which contexts are dropped from `ContextDBMS` (status, job, equip,
   `SubPawnDataContext`), and whether the CharacterID is freed or reused.
2. `PawnManager.lost` / `onLost`: what triggers it, what it drops, whether a lost pawn returns to the Rift list.
3. `hirePawn` and the Rift pawn list: where offline (CAPCOM) pawn data comes from, whether a dismissed pawn reappears
   with the same `_OfflineID`, and whether its level/exp/vocation on re-hire come from the Rift data (owner level?)
   or from anything the game kept.
4. Which events or methods are good hook points to detect dismiss, lost and hire for a given pawn.

Mark each finding verified-dump / inferred; the in-game experiment confirms. Feeds the experiment design.

## Answer

Findings: `docs/findings/research-m2-dismiss-lost-rehire.md` on branch `research/m2-dismiss-lost-rehire` (commit `978e019`,
never merged). The dump has signatures, not bodies: behaviour claims are inferred unless marked.

- **CharacterIDs are reused** (verified-game, existing probe data): `1601809365` was Alder, then Folken (different
  offline ID, exp 0, `IsRestore` false) after Alder's dismissal. The roster cannot key on CharacterID.
- **Dismiss very likely deletes the whole `ContextDBMS` record** (status, job, equipment, `SubPawnDataContext`, owner)
  (inferred: store on/off switches on hire/dismiss, Arisen's Own waiting for record removal, the ID reuse).
- **The only thing kept is the Rift's dismissed list** (`NPCManager.addStrayPawn_DisMissList`, saved in
  `NPCSaveStrayPawnPasts.Dismisses`): generation data (offline ID, look, skills, job, one `Level`). No exp, discipline,
  rank exp or equipment (verified-dump). Whether `Level` is original or current is open.
- **Re-hire** (inferred): offline pawns are generated by `StrayPawnManager`/`StrayPawnFactory` near the player's level;
  a dismissed pawn can return from that list with the same offline ID, possibly a new CharacterID, from exp 0.
- **Lost** (inferred, lower confidence): `setPawnLostTimer` → `onLostCheck` → `pawnLost` → `lost` → `onLost`; nothing shows a
  lost offline pawn entering the dismissed list.
- **Hook points** for the experiment: section 4 of the findings (the three `dismissPawn` overloads, `addStrayPawn_DisMissList`,
  `ContextDBMS.deleteRecord`, `lost`, `setPawnLostTimer`, `hirePawn` post, `getUnusedOfflineCharacterID`,
  `restorePastInformation`, `restoreContextsToHolder`, `FacilityManager.startRim`/`endInteractRimAction`); six open
  questions for the in-game run close the doc.
